# agent_monitor

Python implementation of the **Adaptive Multi-Dimensional Monitoring (AMDM)**
algorithm for agentic AI systems (Shukla 2025, arXiv:2509.00115). Two tiers:

- **Tier 1 (streaming)** — per-axis scores from rolling z-scores + EWMA
  baselines, then a joint Mahalanobis / chi-square anomaly detector over the
  axis-score vector.
- **Tier 2 (sessions)** — per-session squared Mahalanobis distance against a
  winsorized rolling population, feeding a stratified human-review queue.

The library is a hybrid FP/OOP design: all computation is pure functions over an
immutable, Parquet-checkpointable `MonitorState` (frozen dataclasses, read-only
NumPy arrays); I/O is confined to Parquet checkpoint save/load. A thin stateful
`Monitor` facade is provided for long-lived services. Data loading is **out of
scope** — callers supply pre-aligned per-tick metric matrices and raw per-axis
session features.

## Quick start

```python
import numpy as np

from agent_monitor import Monitor, MonitorConfig, TickMetrics, validate_monitor_config

config = validate_monitor_config(
    MonitorConfig(
        axis_names=("safety", "quality", "latency", "cost", "throughput"),
        metric_names=(
            ("refusals", "toxicity"),
            ("hallucinations",),
            ("p50_ms",),
            ("usd_per_task",),
            ("tasks_per_hour",),
        ),
    )
)

monitor = Monitor(config)

# Each tick the caller hands this monitor one aligned metric matrix.
tick = TickMetrics(
    X=(
        np.array([0.1, 0.0]),
        np.array([0.0]),
        np.array([120.0]),
        np.array([0.75]),
        np.array([14.0]),
    )
)
result = monitor.update(tick)
print(result.alert)  # False during warm-up
```

`validate_monitor_config` resolves `k=None` to `chi2.ppf(0.99, df=A)` (the paper
default sensitivity). Run the detailed examples under `examples/` for the full
streaming and batch workflows.

## Airflow-style workflow

The batch path (e.g. an Airflow `PythonOperator`) is:

1. **restore** a checkpoint with `Monitor.restore(path)` (or construct a fresh
   `Monitor(config)` on first run);
2. **advance** the new batch of ticks with `monitor.update(tick)`;
3. **absorb** the batch's sessions with `monitor.absorb(sessions)`;
4. **score** candidates with `monitor.score(sessions)`;
5. **save** with `monitor.save(path)`.

`Monitor.update()` records whether the tick raised an alert, and `absorb()` in
the same tick stamps that flag on the absorbed sessions for downstream
forensics. See `examples/airflow_batch.py` for the runnable end-to-end version.

## Configuration defaults

`MonitorConfig` (paper defaults unless noted). `axis_names` and `metric_names`
are required and fix the topology at construction.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `axis_names` | `tuple[str, ...]` | — | A >= 2 axis names |
| `metric_names` | `tuple[tuple[str, ...], ...]` | — | >= 1 metric name per axis |
| `window` | `int` | `80` | rolling window `w` >= 2 |
| `lam` | `float` | `0.25` | EWMA smoothing, `0 < lam <= 1` |
| `k` | `float \| None` | `None` | per-axis multiplier; `None` → `chi2.ppf(0.99, A)` |
| `alpha` | `float` | `0.01` | joint false-alarm rate |
| `min_warm` | `int` | `30` | joint warm-up ticks >= 2 |
| `ridge` | `float` | `1e-6` | covariance regularization |
| `agg` | `str` | `"mean"` | axis aggregation: `mean` \| `max` \| `l2` |
| `population_window` | `int` | `80` | Tier 2 covariance window (ticks) |
| `min_population` | `int` | `30` | sessions before Tier 2 scoring |
| `winsor_pct` | `float \| None` | `0.99` | two-sided clip percentile; `None` disables |
| `winsor_k` | `int` | `3` | quantile lookback `= window * winsor_k` ticks |

`QueueConfig` budgets are **per build call**; the defaults assume one build per
day — per-tick users must scale them.

| Field | Type | Default | Meaning |
|---|---|---|---|
| `top_k` | `int` | `200` | highest-d² stratum |
| `flagged` | `int` | `150` | sessions from AMDM-flagged ticks |
| `per_axis` | `int` | `100` | `floor(per_axis / A)` per axis, most extreme first |
| `uniform` | `int` | `100` | seeded uniform random draw from remainder |
| `reserved` | `int` | `50` | analyst reserve; never filled by the library |
| `seed` | `int` | `0` | RNG seed for reproducible random strata |

## Assumptions

1. **Caller-aligned inputs** — every tick delivers one complete `A × M` matrix;
   partial/late-arriving axes are a v1 extension.
2. **Session features are caller-supplied** raw per-axis values; the library
   only applies the empirical population transform.
3. **Topology fixed at construction** — changing axes/metrics/`w`/`lam`/`k`/`alpha`
   requires a new state.
4. **Defaults follow the paper** (`w=80`, `lam=0.25`, `k=chi2_A(0.99)`,
   `alpha=0.01`, `min_warm=30`, `ridge=1e-6`, mean aggregation).
5. **No alerting/notifications** — flags and queue plans are return values;
   delivery is downstream.
6. **No metric-encoding guidance** — categorical/boolean metrics are the
   caller's responsibility.
7. **Checkpoint security** — Parquet only (no pickle); loading is data-only.
8. **QueueConfig budgets are per build call** — the defaults assume one daily
   build.
9. **0.0-filled S entries during axis warm-up** feed the joint detector
   (reference-parity choice; negligible for `min_warm >= 30`).
10. **Winsorization on by default** — protects the population from contaminated
    sessions but mildly inflates H0 Tier-2 d² (nominal p-values are
    approximate) and does **not** protect against *coordinated* drift.

## Deferred scope

- **Sensitivity calibration** (`k`, `alpha`) against real production telemetry —
  v1 (risk R-04; the true fix for alert storms / flag thrashing).
- **Partial / late-arriving axes** handling — v1+.
- **Seasonal / contextual anomaly DGP** (periodicity under EWMA baselines +
  rolling z-scores is a calibration question) — v1.
- **plotnine ad-hoc reporting** — v2.
- **Rust/PyO3 kernels** — only if v1 calibration replay profiling justifies it.

## Validity

The DGP catalog (`tests/dgps.py`) **partially** demonstrates the method, and
this claim is deliberately bounded:

- **Demonstrated** on canonical anomaly types mapped to Schmidl et al. (2022):
  layer separation (a coordinated `+1.5σ` shift fires the joint layer only,
  DGP-03), recovery after a point spike and a subsequence burst (DGP-02/DGP-05),
  H0 calibration (Tier 1 flag rate near `alpha` after warm-up, DGP-01), and
  winsor-robust Tier-2 scoring under population contamination (DGP-06).
- **Synthetic evidence only** — the catalog is a *semantics-conformance oracle*
  (does the pipeline exhibit its declared per-type behavior?) rather than ground
  truth from production logs.
- **Per-axis-layer demonstrations are calibration-conditioned** — the catalog
  sets `k = 7.0` with `w = 250` (so `k < sqrt(w)`); the paper default
  `k = chi2_A(0.99) >= chi2_2(0.99) ~ 9.21` exceeds `sqrt(80) ~ 8.94` at the
  default window and makes the per-axis layer inert. Catalog per-axis flags thus
  depend on a sensitivity choice that is **not** the paper default.
- **Independent numerical oracle** — `references/AMDM.py` parity (matched
  `S_A`, `theta`, `D²`, and flags to 1e-9 on the three reference scenarios)
  remains the independent correctness check.
